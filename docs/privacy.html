Lustre Clinic

Privacy policy

Lustre is clinic management software used by one dental practice. This page says what it handles, where that is kept, and what is done with access to a Google account.

Last updated 20 September 2026.

Who this is

Lustre is built and maintained by Youssef Hany Galal. It is not a public service: it is not sold, not listed on any app store, and has no sign-up. It runs for a single dental practice, on a computer that practice owns, and is used by its dentist and secretary.

Clinic records

The practice's own records — patients, appointments, visits, procedures and payments — are stored in a database on a computer inside the clinic. That computer belongs to the practice.

  • These records are not sent to the developer, and are not hosted on any cloud service.
  • Reaching the software requires being on the practice's private network. There is no public address.
  • The practice is the controller of its own patient data and is responsible for it.

The one exception is the off-site backup described next, and it is encrypted.

Google account data

What is requested

Exactly one permission: https://www.googleapis.com/auth/drive.file.

This permission is limited by Google to files the application itself created. Lustre cannot list, read, alter or delete anything else in the account's Google Drive, and does not ask for any permission that would let it.

What it is used for

  • Creating one folder, Lustre Clinic Backups, in the signed-in account's Drive.
  • Uploading the nightly backup of the clinic database into that folder.
  • Listing the backups that folder holds, so old ones can be removed on a schedule.
  • Deleting backups that have aged out — roughly 14 daily, 8 weekly and 12 monthly are kept.

Nothing else. Google account data is not used for analytics, advertising, profiling, training any model, or any purpose unrelated to storing and pruning these backups.

The backup contents

A backup is a copy of the clinic's database, so it contains patient records. It is encrypted on the clinic computer before it is uploaded. The encryption key is not kept on that computer, is not uploaded with the backup, and is not known to Google or to the developer. What is stored in Drive is ciphertext.

Credentials

When the dentist signs in, Google issues a refresh token. That token is stored on the clinic's own server, in a file readable only by the account the server runs as. It is not transmitted to the developer and is not stored on any phone. Short-lived access tokens are held in memory only and never written to disk.

Sharing

Google account data and backup contents are not sold, rented, or shared with anyone. There are no third-party analytics, advertising or tracking services in the application.

Limited Use

Lustre's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Withdrawing access

The signed-in account can revoke Lustre's access at any time at myaccount.google.com/permissions. Backups already in Drive are unaffected and remain the account holder's to keep or delete. Once revoked, the clinic's off-site copies stop; the software reports this so it is noticed rather than discovered later.

Retention

Backups in Drive are pruned automatically on the schedule above. Deleting the Lustre Clinic Backups folder removes them all. Records held on the clinic's own server are retained by the practice according to its own obligations.

Crash reports

Errors from the phone application are collected to diagnose faults. They are sent to software running on the clinic's own server, not to any third-party service, and are limited to error codes, screen names and application version. Patient names, phone numbers, notes and amounts are excluded.

Changes

If what the software does with Google account data changes, this page changes with it, and the date at the top is updated.
